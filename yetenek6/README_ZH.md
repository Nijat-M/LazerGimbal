# Yetenek 6 — 目标探测与分类：分步实施指南

> **要求原文**：5 m、10 m、15 m 三个距离上完成不同目标类型的探测与分类，并**在用户界面上展示**能分类为 **F16 / Mini-Micro İHA / Füze / Helikopter**。
>
> **前提**：你们相机 + UI 已跑通，PC 带独显，只有 3MF 文件，目标是**先过视频这关**。
>
> **总工时**：约 17–28 小时。两人并行 1.5–2 天。

---

## 核心思路：为什么不用人工标注

你们有 3MF（三维网格文件）。用它可以**同时**做两件事：

1. **渲染出多视角贴图素材** → 合成训练图像，**边界框由程序自动算出**，人工标注量 = 0
2. **渲染出高分辨率正视图** → 送打印店做实体靶标

因为视频里的靶标是**平面打印件**，而合成数据本质上就是"把平面素材贴到背景上"——**仿真和现实高度一致**，这是这套方案精度能上来的根本原因。

**不要为了视频去 3D 打印靶标。** 一个 60 cm 的模型拆件打印要 20–40 小时，四类目标一周起步，来不及。规范能力 6 的原文分类对象就是「görseller（图像）」，打印平面靶标完全合规。

## 步骤 0 — 20 分钟的可行性体检（**千万别跳过**）

整个方案成败取决于一个数字：**15 m 处目标有多少像素**。先量出来。

**A. 测相机水平视场角（HFOV）**

1. 拿一个已知宽度的物体（比如 1.00 m 的纸板），放在**正好 5.00 m** 处
2. 用你们的相机拍一帧，在看图软件里量出它的**像素宽度**
3. 运行：

```bash
cd scripts
python s0_kamera.py --img_w 1920 --ref_m 1.0 --ref_d 5.0 --ref_px 640 --target_m 0.6
```

**B. 看输出的判断**

| 15 m 处像素宽 | 结论 |
|---|---|
| ≥ 80 px | 很好，直接往下走 |
| 45–80 px | 可以，训练/推理必须用 `imgsz 960` |
| 28–45 px | 临界，用 `imgsz 1280` **并且加大靶标** |
| < 28 px | **不行**，必须加大靶标或换窄视场（长焦）镜头 |

脚本最后会直接告诉你：**要在 15 m 达到 60 px，靶标需要多宽**。按这个数字去定打印尺寸。

> 规范对靶标/图像的尺寸**没有任何限制**，所以最省事的解法就是把靶标做大。60–80 cm 是个安全区间。

## 步骤 1 — 从 3MF 生成素材和打印图（约 30 分钟）

```bash
cd scripts
python s1_render.py --models_dir ../models_3mf --out ../out \
    --views 200 --size 512 --poster_cm 60 --poster_dpi 150
```

输出两样东西：

| 目录 | 内容 | 用途 |
|---|---|---|
| `out/sprites/<类别>/` | 每类 200 张多视角透明 PNG | 步骤 3 合成训练数据 |
| `out/posters/` | 每类 3 个颜色（红/蓝/灰）的 60 cm @150dpi 大图 | 步骤 2 送打印 |

**关键参数说明**

- `--az_range -38 38`：水平视角范围。**因为最终拍的是平面靶标，这里要收窄**（默认已收窄）。如果你们决赛要拍 3D 实体，再放宽到 `-180 180`
- `--colors kirmizi,mavi,gri`：红=敌、蓝=友、灰=中性。红蓝两色**顺便把能力 7 的素材也做出来了**，不用重复工作
- 不需要 Blender，纯 numpy + Pillow，Windows 上直接能跑

只要打印图不要训练素材时加 `--poster_only`（几秒钟出结果）。

---

## 步骤 2 — 今天就把靶标送去打印（**这是唯一的外部依赖，最容易卡住**）

拿 `out/posters/*.png` 去打印店：

- **规格**：60 cm 宽（或步骤 0 算出来的尺寸）、哑光相纸或 PP 背胶
- **裱板**：KT 板 / 泡沫板，**沿飞机轮廓裁形**（不要裁成方块——方块会让模型学到"矩形=目标"这种错误特征）
- **数量**：四类各 1 张灰色/红色版即可满足能力 6；能力 7 另需 1 红 2 蓝
- **支架**：每张背后粘一根细木条 + 简易三脚支撑，能立在地上

> 打印店当天到隔天出货。**今天下单**，别等到模型训完才想起来。成本几十里拉。

---

## 步骤 3 — 拍 30–40 张场地背景照（30 分钟，**决定精度上限**）

去你们**实际要拍视频的场地**，用**同一台相机、同样的架设高度**，拍 30–40 张空场景照片（不放靶标），涵盖：

- 不同朝向、不同时间段的光照
- 有人走动、有杂物的画面
- 阴天/晴天各来一些

放进 `backgrounds/` 目录。

> **这一步是整套方案里性价比最高的 30 分钟。** 用真实场地背景合成的数据，比用程序生成的假背景，实测精度差距非常大——因为模型不会再把背景里的杂物误判成目标。跳过这步，脚本会自动用合成背景，但误检率会明显上升。

---

## 步骤 4 — 合成训练数据集（15–25 分钟机器时间）

```bash
python s2_dataset.py --sprites ../out/sprites --bg ../backgrounds \
    --out ../dataset --n_train 5000 --n_val 500 \
    --img_w 1920 --img_h 1080 --hfov 60 --target_m 0.6
```

> `--img_w/--img_h` 填**你们相机的真实分辨率**，`--hfov` 填步骤 0 量出来的值，`--target_m` 填靶标实际宽度。

脚本干了什么：

- 目标在画面中的像素尺寸由**真实光学公式**推算：`px = img_w × 靶标宽 / (2 × 距离 × tan(HFOV/2))`
- **55% 的样本集中在 5/10/15 m 附近**（±15% 抖动），其余在 3.5–18 m 均匀分布 —— 精准对齐规范要求的三个距离
- 随距离增加模糊、亮度/对比度抖动、噪声、JPEG 压缩、旋转
- **边界框从 alpha 通道自动精确算出**，写成 YOLO 格式
- 自动生成 `data.yaml`

运行完会打印一张**像素尺寸参考表**，再确认一次 15 m 的数值合理。

---

## 步骤 5 — 训练（1–2 小时，挂机）

```bash
python s3_train.py --data ../dataset/data.yaml --model yolov8s.pt \
    --imgsz 960 --epochs 80 --batch 8 --device 0
```

**⚠️ 最容易犯的错：用默认 `imgsz 640`。**
15 m 处目标只有 40–60 px，640 输入下会被压到 15–20 px，小目标召回会断崖式下跌。**必须用 960，紧张的话用 1280。**

其他建议：

- 显存不够就调 `--batch 4`，或换 `yolov8n.pt`（更快、精度略低，对四类靶标够用）
- 训完看 `runs/detect/yetenek6/`：**mAP50 ≥ 0.85** 就可以进入下一步
- 权重在 `runs/detect/yetenek6/weights/best.pt`

---

## 步骤 6 — 真实数据微调（**强烈建议，2 小时，效果最明显**）

靶标打印回来后，在场地上按 5/10/15 m 摆好，**每类录 30 秒视频**，抽帧得到 150–300 张真实图。

- 用 [Roboflow](https://roboflow.com) 或 `labelImg` 标注 —— 只有 200 来张，**一个人 1 小时能标完**
- 混进 `dataset/images/train`，用合成模型做起点再训 20–30 epoch：

```bash
python s3_train.py --data ../dataset/data.yaml \
    --model runs/detect/yetenek6/weights/best.pt \
    --imgsz 960 --epochs 30 --name yetenek6_ft
```

这一步通常能把真实场景的 mAP 再拉高 10–20 个点，是**合成数据方案的标准收尾**。

## 步骤 7 — 接进你们现有的 UI（3–5 小时）

因为相机→界面链路已经通了，改动量很小：

```python
from s4_detector import HedefDedektoru

# 初始化一次
self.det = HedefDedektoru("best.pt", conf=0.35, imgsz=960,
                          hfov_deg=60, hedef_genislik_m=0.6)   # 后两个参数可选

# 原来的每帧循环里：
#   self.label.setPixmap(self.mat2pix(frame))
# 改成：
dets = self.det.tespit(frame)
self.label.setPixmap(self.mat2pix(self.det.ciz(frame, dets)))
self.tablo_guncelle(dets)      # 右侧分类列表
```

`dets` 是标准结构，方便你们接自己的逻辑：

```python
[{'sinif': 'F16', 'gorunen': 'F16', 'guven': 0.94,
  'box': (x1,y1,x2,y2), 'mesafe_m': 5.1}, ...]
```

`s5_ui_pyqt.py` 是一个可直接运行的完整 PyQt 面板（左边视频 + 右边分类表格），可以整段抄，也可以直接拿来当演示界面：

```bash
python s5_ui_pyqt.py --weights best.pt --source 0 --hfov 60 --target_m 0.6
```

**界面细节（裁判会看这些）**

- 标签用 PIL 绘制，正确显示土耳其字符 `Füze`、`İHA`（`cv2.putText` 显示不出来，这是个常见坑）
- 每类一个固定颜色，右侧表格实时列出 **HEDEF TİPİ / GÜVEN / MESAFE**
- 顶部信息条显示当前检测数量

> **距离显示是加分项，不是必需项。** 规范原文只要求「在这三个距离上完成探测和分类，并通过用户界面展示」——距离是**布置条件**，不是界面必须输出的数值。给 `hfov_deg` 和 `hedef_genislik_m` 就能顺带估出距离，不给就显示 `-`，**不要为此单独做测距模块**。

## 排障速查

| 现象 | 原因 / 解法 |
|---|---|
| 15 m 完全检不到 | `imgsz` 太小 → 上 1280；或靶标太小 → 重回步骤 0 重算尺寸 |
| 背景杂物被误检 | 没用真实场地背景 → 补做步骤 3，或降低 `--conf` 阈值反向验证 |
| 类别互相混淆 | 素材视角范围太宽 → 收窄 `--az_range`；或补真实数据微调（步骤 6） |
| 帧率太低卡顿 | 换 `yolov8n`；或推理降到 `imgsz 640` 但只对画面中心 ROI 裁剪后送入 |
| UI 上土耳其字符是方块 | 用 `s4_detector.ciz()`（PIL 绘制），别用 `cv2.putText` |
| 3MF 加载报错 | 用 PrusaSlicer / Bambu Studio 打开后导出 STL，把 `s1_render.py` 里的 `*.3mf` 改成 `*.stl` |
| 训练 loss 不降 | 检查 `data.yaml` 的 `names` 顺序和 `sprites/` 子目录名是否一致（脚本按字母序编号） |
